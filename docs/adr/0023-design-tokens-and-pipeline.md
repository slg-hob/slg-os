# 0023. Design tokens, token pipeline and Bootstrap mapping

- Status: Proposed
- Date: 2026-10-20

## Context
PRD-0005 (visual language, approved 2026-10-19) asks for one source of design tokens that generates the `--slg-*` custom properties, a Bootstrap 5.3 build that follows the tokens, an automated contrast check, lint rules that keep modules on tokens, and pinned, licensed assets. Decisions D2 (token source, generated outputs, Bootstrap map, contrast check) and D3 (typeface Source Sans 3, decided by the owner on 2026-10-19, Q49) are recorded here. Milestone V1 delivers the pipeline; fonts, icons and the product mark follow in V2. The numbers 0014 to 0022 are announced by PRD-0003 and PRD-0004, so this ADR takes 0023 as announced in PRD-0005 section 7.5.

## Decision

**Token source.** Tokens are JSON files in `design/tokens/` (`color`, `type`, `space`, `radius`, `shadow`, `motion`, `size`), each a list of entries (name, values, usage). Next to them: `design/pairs.json` (the contrast pairs), `design/bootstrap-map.json` (which `--bs-*` variable is set from which token, plus the Bootstrap pairs) and `design/tokens.schema.json`. A built-in validator (no dependency, no network) checks the schema, unique names, the required colour tokens of VL-2 AC1, and the references between files. Pair lists carry a role, not a threshold: `text` 4.5, `large-text` 3, `ui` 3, `hairline` 1.5 and `disabled` 1.5 (disabled controls are exempt from WCAG 1.4.3 but stay perceivable). A pair file cannot lower its own threshold (the schema rejects the field).

**Generator.** The workspace package `@slg-os/design-tools` (`frontend/design-tools`) generates into `frontend/design-system/src/generated/`: `tokens.css`, `bootstrap-map.css`, `_tokens.scss`, `tokens.ts` and `pairs.json`. The files are committed; `npm run tokens:check` (CI job `design`, the PRD's `tokens-sync`) regenerates in memory and fails on any difference, a missing file or an unknown file in the directory. The PRD names `packages/design-system/` and `design/check-contrast`; the repository layout of ADR-0013 uses `frontend/`, so the paths are `frontend/design-system/` and `npm run contrast` in `frontend/`.

**Themes in CSS.** Light values live under `:root, [data-bs-theme="light"]`, dark under `[data-bs-theme="dark"]` (the shell sets the attribute; `auto` is resolved by the shell, Bootstrap does not know it). `@media (prefers-contrast: more)` overrides the tokens that have a high-contrast value (`lightHc`, `darkHc`); the selectors are chosen so a high-contrast light rule never beats the dark theme. `@media (forced-colors: active)` maps every token to a system colour keyword (`forced` field) and removes shadows. Every opaque colour also gets a `--slg-<name>-rgb` triplet because Bootstrap uses `rgba(var(--bs-*-rgb), ...)`.

**Contrast check.** `npm run contrast` evaluates every pair in four modes (light, dark, light high-contrast, dark high-contrast) with the WCAG 2.2 formula. For glass it composites `surface-glass` over black, white and the two wallpaper bound colours (`wallpaper-darkest`, `wallpaper-lightest`) with the sRGB alpha formula and ignores blur. Verified values match PRD-0005 VL-2 AC2 (for example `ink-muted` on raised 7.00 and 6.87, `link` 5.40 and 7.05, `control-border` 4.74 and 4.49, `primary` label 5.98). The self-test is a unit test with deliberately failing token fixtures and a CI fault patch (`ci/selftest/`, fault `token-contrast`) that turns the check red. Two roles go beyond VL-2 AC5 and amend it: `hairline` (1.5, dividers) and `disabled` (1.5), plus `text-enhanced` (7.7) that gates the status pairs at the PRD's "at least 7.7:1". The PRD quotes light glass over black as 8.0:1; the computed value is 8.95:1 with the formula above (the number in the PRD is to be corrected). In the high-contrast and forced-colour modes the tokens switch glass to its solid fallback and drop shadows. The check works on tokens; the Playwright checks on rendered pages (wallpaper luminance, computed styles) arrive with the catalogue (V2/V3a).

**Bootstrap.** Bootstrap 5.3.8 is built from SCSS with the generated Sass maps. Bootstrap 5.3 is written with `@import`, so `@use ... with` (PRD-0005 VL-5 AC2) does not reach its variables; the build sets the variables before the import instead and silences the deprecation warnings that come from Bootstrap's own sources (`import`, `global-builtin`, `color-functions`, `if-function`). Dart Sass 3 will remove `@import`; the Bootstrap version that migrates to `@use` removes the workaround. At run time `bootstrap-map.css` sets the `--bs-*` variables from the tokens, after Bootstrap's own rules, so a theme switch needs no rebuild. A check in `tokens:check` fails when platform code (shell, design system) uses a `--bs-*` variable that is not mapped. The rendering check of used Bootstrap components in both themes (computed styles) needs a browser and arrives with the catalogue. Bootstrap defaults that Sass variables cannot theme at run time are corrected in `design-system/src/styles/overrides.css`, which the build appends last and which reads tokens only: one focus ring drawn as an outline (Bootstrap's glow is a 1.28:1 box-shadow that forced colours removes), control borders from `control-border`, solid raised surfaces for cards, modals, dropdowns and list groups, and the primary button states. The success, warning and danger fills are not remapped at run time, because Bootstrap derives its label colour (white or dark) from the light fill at build time and a lighter dark-theme fill would break it.

**Data URLs.** Bootstrap draws check marks, chevrons and close icons with `data:` SVG URLs, which the CSP (`img-src 'self'`) blocks and VL-13 AC4 forbids. V1 switches these Sass variables off (the 25 occurrences), so checkboxes, radios, switches, selects, accordions, carousel and close buttons show no glyph until V3c restyles the state components with bundled SVG files. The style build fails on any `data:` or network URL and on a gzip size above 60 KB (NFR-V3); the current size is about 32 KB.

**Lint.** `@slg-os/eslint-config` (module code: no raw colours, inline styles, `--bs-*`, password inputs, `slg-shell-*` or `slg-glass` classes) and `@slg-os/stylelint-config` (no raw or named colours, no `!important`, no global selectors, no `--bs-*`, no `data:` or network URLs, no `@import`; a looser platform variant for shell and design-system) are workspace packages with behaviour tests. The reference module is linted with them from now on. The prefix `slg-shell-` is reserved for shell dialogs and notices (VL-10 AC7).

**Typeface (D3).** Source Sans 3 (OFL 1.1, `@fontsource-variable/source-sans-3`) replaces Murecho by the owner's decision. The font stack is a token (`font-sans`); the files, hashes and the 150 KB font budget arrive in V2. If the budget is missed, a follow-up decision chooses between fewer subsets and a larger budget, as NFR-V3 states.

**Assets and licences.** `docs/design/assets.lock` records source, version, hash and licence of every shipped third-party asset (Bootstrap in V1). `npm run assets:check` verifies npm assets against `package-lock.json`, file assets by SHA-256, `THIRD-PARTY-NOTICES`, and the licence of every package in the lock file against an allowlist (permissive licences and MPL-2.0 for build-time tools). A package without a licence field needs an exception with evidence (`svg-tags`, a transitive dependency of Stylelint). A new licence or exception needs the owner's review (CODEOWNERS).

**Dependencies.** Added to the version table: `bootstrap` 5.3.8, `sass` 1.105.2, `stylelint` 17.16.0 (exact versions, lock file, `ignore-scripts`). Stylelint's dependency chain (`globby`, `fast-glob`, `micromatch`, `braces` 3.0.3) is flagged as high severity by the advisory database (GHSA-vfj7-8cjw-p6xm, no fixed `braces` release exists). Stylelint runs only in the build on trusted repository files and never with user input, so the finding is accepted until Stylelint drops the chain; it is listed with a reason and an expiry date in `ci/trivyignore.yaml`.

## Consequences
- Changing a colour, radius or type step is a JSON edit plus `npm run tokens:generate`; CI fails when the generated files are stale or a pair no longer passes.
- Removing or renaming a required token fails validation, which makes the "breaking change" rule of VL-5 AC4 mechanical; the token diff report of VL-14 AC2 is not part of V1 and follows with the contract work (V7).
- The first visible glyph gap (Bootstrap icons) is a known, documented regression until V3c; no shipped screen uses these components yet.
- Not done in V1, to be added with the components they belong to: hover, pressed and disabled tokens and pairs for the danger, success, warning, secondary and outline button variants (V3c), `.btn-sm` and `.form-check-input` target sizes (VL-4 AC3), a `prefers-color-scheme` fallback before the shell sets `data-bs-theme` (V5 for the pre-session pages), and `min(22rem, 100vw)` for the main menu width (V3b). Module CSS may declare its own non-`bs` custom properties; only `--bs-*` and non-token colours are rejected.
- Module lint cannot stop determined evasion (string concatenation, importing a file named `*.test.tsx`); it stops accidents and makes violations visible in review, and the kit checks of VL-14 AC3 plus the hostile-fixture test of VL-10 AC7 add the runtime side. The module repositories must opt in to the shared configuration, which the module kit (B7) makes mandatory.
- Dart Sass 3 will force a decision when Bootstrap has not migrated; the pinned versions make this a deliberate upgrade.
- `design/**`, the lint packages, `assets.lock` and the tooling need CODEOWNERS review, so the owner sees every change to the contract.

## Alternatives considered
- **Style Dictionary** as generator: more features, but a large dependency tree for a few outputs, and the PRD asks for a generator with pinned dependencies and byte-equal golden outputs; the own generator is about 150 lines.
- **Authoring tokens in TypeScript or CSS:** loses the schema validation, the list shape and the use by non-TypeScript consumers (Sass, Keycloak theme in V5).
- **`@use ... with` for Bootstrap:** not possible with Bootstrap 5.3 (see above).
- **Generated files not committed:** every consumer would need the generator in its build; committed files make reviews show the effect of a token change.
- **Skipping Stylelint and checking CSS with regular expressions:** cheaper in dependencies, but weaker (comments, strings, nesting) and not what PRD-0005 VL-5 AC3 specifies.
